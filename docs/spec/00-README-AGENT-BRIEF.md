## Locked decisions (do not re-litigate)
- Backend: **Python 3.12, Django 5.x, Django REST Framework, drf-spectacular (OpenAPI), PostgreSQL 16, Redis, Celery + Celery Beat**, django-storages (S3-compatible), django-filter, django-guardian-style object permissions (or custom policy layer), Sentry.
- Frontend: **Next.js (App Router, TypeScript strict), shadcn/ui + Tailwind, TanStack Query, react-hook-form + zod, Tiptap (WYSIWYG), TanStack Table, Recharts, Zustand (UI-only state), next-intl (i18n-ready), Playwright + Vitest.**
- API contract: OpenAPI generated by drf-spectacular; frontend client generated with `openapi-typescript` + `openapi-fetch`. No hand-written duplicate types.
- Video: **Mux** (direct upload, HLS adaptive, signed playback JWT, captions). Abstract behind a `VideoProvider` interface so S3+MediaConvert+CloudFront can replace it.
- Payments: **Paystack** only (NGN default; kobo integers everywhere). See file 03.
- Auth: email+password and Google sign-in; JWT access (15 min) + rotating refresh in httpOnly cookie; OIDC-provider-ready for SSO later.
- Currency: money = `BigIntegerField` in minor units (kobo) + ISO currency code. Never floats.
- Timezone: store UTC, default display `Africa/Lagos`.

## Working rules for the agent
1. Build in the milestone order of file 09. Each milestone must end green: migrations, tests, lint, typecheck, seed data, README update.
2. Every endpoint: serializer validation, permission class, pagination, filtering, OpenAPI docs, tests (happy path + permission denial + validation).
3. Every mutation of money, grades, enrollment, certificates writes an **AuditLog** row.
4. Every list screen needs loading, empty, error and partial states (see 07).
5. Everything configurable lives in the database (admin-editable), not in code: grading schemes, fee rules, form fields, certificate templates, email templates, branding.
6. Ask no questions for details covered here; where genuinely ambiguous, choose the simplest option, record it in `/docs/DECISIONS.md`, move on.
